# Emma application audit — August 28, 2026

## Result

**12 independently confirmed bugs fixed: 4 P1, 8 P2. No P0 was confirmed.** Discovery, reproduction, implementation, and review used separate GPT-5.6 Sol agent assignments, in waves of up to three workers. Each issue had its own fix worktree. Reviewers required corrections before accepting five of the initial fixes.

The accepted changes are integrated into the working tree of `feat/mobile-bridge`. Existing work was preserved: all 1,233 original files were checked before application; all 1,245 candidate files matched afterward. HEAD remains `a9290c5`, and the index is unchanged. This is a working-tree integration, not a merge commit that also commits your unrelated changes. The reviewed candidate is `5f3ac20` on `codex/audit-candidate`.

**No regressions were observed in the completed checks below. This is not a guarantee of zero bugs or complete accessibility coverage.** Untested areas and two unconfirmed harness leads are listed explicitly.

## Confirmed fixes

| ID | Priority | Problem and root cause | Fix and expected behavior |
|---|---|---|---|
| STOP | P1 | A verifier or human approval could finish after Stop and still authorize a tool. | Authorizations are tied to a live run identity and rechecked after asynchronous work. Stopped or replaced runs cannot execute late approvals; unrelated and surviving child runs retain their own approvals. |
| MODE | P1 | Tool calls used a permission mode captured earlier, ignoring a live switch from Full access or Auto to Ask. | Read the active mode at authorization time and recheck after verification. Descendants inherit changes. The mode shown by the UI now governs subsequent authorization decisions. |
| SNAPSHOT | P1 | A snapshot exceeding the 16 MiB NDJSON line limit permanently killed the host connection. | Rust sends request-correlated 64 KiB chunks; Electron validates and reassembles them. Large histories load without losing the host. The 256 MiB aggregate ceiling rejects the request without killing the connection. |
| SCHEDULE-IPC | P1 | Every UI schedule create/edit included `model`, which IPC rejected. Empty inherited models were also rejected. | Permit `model` and its empty inheritance value only for this method. Create and Save work while unknown fields, invalid types, oversized inputs, and empty required fields remain rejected. |
| IME | P2 | Composer shortcuts could submit or select commands while an input method was composing text. | Leave composing key events to the IME in the thread composer, overlay, and schedule prompt. Ordinary Enter and Shift+Enter behavior is retained. |
| HISTORY | P2 | Up/Down history navigation discarded the current draft; Up with no history could clear it. | Capture and restore the draft when entering/leaving history. Empty history and boundary navigation leave text intact. |
| QUEUE | P2 | Asynchronous attachment preparation could reorder submissions and clear a later draft's attachments or skill. | Consume the submitted context synchronously and prepare it inside the existing FIFO queue. Later picks remain attached to their draft; context-bearing queued messages cannot be steered as plain text. |
| RAW-CRON | P2 | Choosing the raw Cron editor for a recognizable preset immediately switched back to the preset. | Keep the editor choice locally without rewriting the schedule. Raw expressions remain editable; switching presets still works. |
| CRON-BOOKING | P2 | Editing cron rebooked from the original creation date, producing past or immediate runs. | Book changed cron from the current time, preserve creation/history, and retain existing bookings for unchanged expressions. Sparse schedules and leap-day jobs survive edits and reloads. |
| EDITS | P2 | Truncated/stringified harness tool previews lost file paths, so Changes/Revert could miss actual edits. | Carry complete edit paths separately from previews and capture them against the active run. Revert accepts contained long paths while retaining workspace validation. Large writes appear in Changes and restore correctly. |
| PROVIDERS | P2 | A newly added provider appeared saved but immediate Use failed until reload because main's registry was stale. | Register before publishing saved settings; await add/remove and show errors. Restore the previous registry if persistence fails. Newly added profiles work immediately. |
| SCHEDULE-MODEL | P2 | Unpinned tasks looked up the fresh run thread's empty model context, ignoring the selected app model. | Use the selected app model when the job has no explicit pin. Local-model schedules work after restart; explicit provider/OpenRouter/router pins retain precedence. |

## What independent review caught

These corrections were made before acceptance:

- Prevent steering a queued message while its attachment preparation is still pending.
- Do not cancel surviving child approvals merely because the parent starts another turn.
- Preserve sparse cron bookings on reload and allow unchanged leap-day schedules to be renamed.
- Allow safe long relative paths during Revert instead of applying the shorter capability-ID limit.
- Roll back the provider registry when local settings persistence fails, including removal failures.

The combined suite also exposed a stale active-turn test fixture and a CommonJS fixture incompatible with repository lint rules. Both fixtures were corrected without weakening their assertions. Source comments in edited files were removed under `AGENTS.md`; that accounts for much of the deletion count.

## Limits and rollout notes

- **Not exercised:** VoiceOver itself, a native Japanese/Chinese IME session, OS privacy permission grants, global Quick Ask shortcuts, multiple displays, alternate scaling/window geometry, signing/notarization, non-macOS paths, live commercial model providers, or the complete remote/platform CI matrix. Unicode paste and handler tests are not substitutes for native IME testing.
- Two static Zig leads remain **unconfirmed and unfixed**: child-context ownership across parent refresh in ACP, and error-path cleanup in `gateway/emma_openai.zig` tool-call parsing. Independent runtime reproduction was not completed; neither is counted among the 12 confirmed bugs.
- Global router selection currently stores its first OpenRouter model in main's selected-model state. Scheduled inheritance follows that existing representation; explicit scheduled router pins retain their full chain. This audit did not redesign router selection.
- Snapshot reassembly still holds the complete result in memory and has a 256 MiB ceiling. This is transport resilience, not unlimited-history streaming.
- The existing renderer bundle-size warning remains. No dependencies, persisted-data migrations, version bumps, release tags, or changelog edits were added.
- Ship Electron, the Rust host, and the Zig harness together: chunked responses and complete edit-path metadata cross those boundaries. The local checks support these fixes, not a release-wide zero-regression certification.
